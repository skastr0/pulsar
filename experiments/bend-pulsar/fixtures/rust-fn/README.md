# Rust function and control-tree fixtures

Hand-checked expectations for the Rust adapter's `M`, `FN`, `FK`, `CT` and `.fns` output
(#657). Owner of the adapter: pulsar-rs. Owner of this fixture: pulsar-cov. The diff test
lives in `cli/src/lang/rust/` and reads these files; nothing here is generated by the
adapter, so a change in the adapter's output has to be argued against a hand count.

## Expected files

One pair per source file, in `expected/`, both TAB-separated, ids local to the file.

`<file>.fns`, one row per function in local id order (id = row number):
`start_line end_line parent kind chain`

- `parent` is the enclosing function's local index, or `-`.
- `kind` is the `FK` kind from FACTS.md: 0 declaration, 2 anonymous function expression
  (a Rust closure), 3 method. Rust has no getters, setters or static blocks.
- `loc` is not pinned here: FACTS.md defines it (non-blank lines in the span, nested
  functions included) and it is arithmetic, not a fixture decision.

`<file>.ct`, one row per control-tree node in preorder, ids 1..k per function:
`fn node parent kind`

- `fn` is the function's local index, `parent = 0` is the function body.
- Kind numbers are FACTS.md's: 1 branch, 2 arm, 3 multi-branch, 4 loop, 6 short-circuit,
  7 early exit, 8 nested-function boundary, 9 default flag, 10 finally arm.
- An empty file means the file's functions have no control nodes.

## What each file pins

| File | Pins |
|---|---|
| `branch.rs` | `if` with an `else if` chain (the nested branch is inside the else arm), `if let`, a branch nested in a then arm, no arm for a missing `else`. |
| `loops.rs` | `while`, `for` and `loop` as kind 4 with no arm; `return` and `break` inside a loop body as kind 7 under the arm. |
| `match_expr.rs` | `match` as kind 3, one kind-2 arm per clause, no flag without a wildcard, a kind-9 flag with `_`, and a guard adding no node of its own. |
| `try_ops.rs` | every `?` as a kind-7 leaf at the body root, and `return` inside an `if` arm as kind 7. |
| `closures.rs` | closures as `ARROW` 2 with their own span and `#<ordinal>` chain names, three levels deep, and a kind-8 leaf in each parent's tree. |
| `impls.rs` | inherent method chain `Type>method`, trait impl chain `Type as Trait>method`, a body-less trait method emitting no `FN`, `async`, generic and associated functions as kind 0 or 3. |
| `skipped.rs` | an `if`-like condition hidden in a macro emitting nothing, and `#[cfg(test)]` items (a function and a whole module) emitting no `FN`. |
| `lib.rs` | module declarations only: no functions, no control nodes. |

## Coverage expectation (`expected-cv.txt`)

The same crate doubles as the Rust coverage fixture: `src/lib.rs` has a `#[cfg(test)]` module,
`reports/lcov.info` is `cargo llvm-cov --lcov` output with crate-relative `SF:` paths, and
`expected-cv.txt` is `path<TAB>chain<TAB>covered/coverable` for every function with data.
`fns.tsv` is the global-id form of the `.fns` rows in `expected/`, and `paths.txt` is the file
list, because `src/lib.rs` has no functions but does have coverage lines.

Hand checks, from the `DA:` lines in `reports/lcov.info`:

| Function | Expected | Why |
|---|---|---|
| `branch::grade` | 6/7 | DA 1, 2, 3, 4, 5, 7, 9; only line 5 (`'B'`) is never taken. |
| `match_expr::label` | 5/6 | DA 13, 14, 15, 16, 17, 19; line 16 (`1 => "one"`) is never taken. |
| `impls::fetch_len` | 0/3 | an `async fn` whose body is never polled by a test. |
| `skipped::macro_hides_if` | 4/4 | the macro's tokens are not coverage lines. |

Unassigned lines are 51 and that is asserted: 45 from the `#[cfg(test)]` module in
`src/lib.rs` and 6 from the `#[cfg(test)]` items in `src/skipped.rs`. Those items emit no `FN`
(a decision recorded in `README.md` of the adapter lane), so their lines belong to no function
span and produce no `CV`, which is exactly what "no data" has to mean here.

`bash regen.sh` regenerates the lcov and prints the first `SF:` line; the expectation itself is
hand-checked, never regenerated.

## Test functions and anonymous ordinals (settled)

pulsar-rs's emitter now agrees with this fixture on every row, after three flips on the
fixture side, all made here:

- `#[cfg(test)]` items are ordinary `FN` rows flagged `TF`, so `expected/lib.fns` has the seven
  `#[test]` functions chained `tests>branch_arms` and `expected/skipped.fns` has
  `test_only_helper` and `tests>runs_only_under_test`. `expected/lib.ct` stays empty: a test
  body is one assertion macro per line, and macro tokens are not control nodes.
- Anonymous ordinals are 0-based and agree with the TS lane: `doubled>#0`,
  `nested_closures>#0>#0`.
- A trait impl keeps the trait's generics in the container name so two impls cannot collide:
  `Meters as From<f64>>from` and `Meters as From<i32>>from`, while the self type drops them.

With test functions in `fns.tsv`, every line llvm-cov instruments belongs to a function, so
`expected-cv.txt` has 39 rows and the coverage test asserts `unassigned == 0` — the earlier
51-line assertion was the no-FN-for-tests rule, and it is gone with the rule.

## Settled decisions encoded in these expected files

pulsar-rs confirmed all of these on 2026-11-07; each was uncertain when the fixture was first
written, and the two "extra pins" they asked for are in `branch.rs` and `loops.rs`.

1. **Wildcard flag position.** A `match` with `_` emits the kind-9 flag as a child of the
   multi-branch, in source order at its wildcard clause, so `match n { 0, 1, _ }` is arms
   2, 3, 4 then flag 5.
2. **Closure boundary parent.** Each kind-8 leaf sits at `parent = 0`, because every closure
   in `closures.rs` is declared in a function body rather than inside an arm or loop.
3. **Closure spans.** A closure's span starts at its `|` and ends at its last body token, so
   `|v| v * 2` on line 2 is `2 2`, and the block-bodied closure on lines 10-13 is `10 13`.
4. **Trait impl chain.** `impl Reset for Counter` names its container `Counter as Reset`, so
   the key does not collide with an inherent `Counter>reset` and does not depend on impl order.
5. **Body-less trait method.** `fn reset(&mut self);` in the trait emits no `FN`; only the
   implementation does.
6. **No arm for a loop.** Loop bodies contribute their inner nodes directly to the loop node,
   so `while i < limit { total += i; }` is one kind-4 node and nothing else.
