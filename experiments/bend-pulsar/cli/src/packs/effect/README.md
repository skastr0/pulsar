# packs/effect

Effect pack, framework-specific and switched on by evidence (an `effect` dependency), never part of the generic baseline. Owner: pulsar-ts-effect. It will emit `SV` (services), `LY`, `LQ`, `LP` (layers), `US` (service use), and `SY`, `CL`, `CS`, `HD` classes from its catalogs (`effect`, `@effect/sql`). Rows go through `crate::facts::FactWriter`.

## catalog/

Pack catalogs in the `pulsar-catalog 0` format (documented by `pulsar catalog --help`), embedded in the binary:

- `effect.toml`: the `effect` pack. It covers effect v3 and v4, `@effect/sql`, `@effect/sql-pg` and the `@effect/platform-*` runtimes. It holds symbols for classes 1 to 8, plus error handlers, generator wrappers, external services and external layers. Its `rules` (`effect.ambient-read-in-effect`, `effect.blocking-in-effect`, `effect.runtime-escape-in-effect`) are the only entries that make findings: each becomes an `RL` row for `engine/ClassCtx.bend` when the pack is active, firing in ctx bit 2 (pack-defined effect context) and not in tests (bit 4).
- `platform-node.toml`: the `platform-node` pack. Its activation evidence is `dep:@types/node` or `import:node:*`. It covers sync `fs` and `child_process` (blocking), `Date.now`, `new Date()`, `Math.random`, `process.env`, `performance.now` (ambient-read), and `console.*` (log). This is runtime knowledge, not Effect knowledge, so it is its own pack.

Both files are generated by `gen_catalog.py`, which checks every entry against the real source. A missing export is a hard error. Each entry cites the JSDoc line that justifies its class (`at`, `doc`), or its signature line when the export has no prose doc. Edit the generator, never the TOML. `python3 -I gen_catalog.py --check` exits 1 when a committed file is stale.
